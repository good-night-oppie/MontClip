Harness correction and side effect: first attempt used removed clipboard.availableFormats API and failed before writing. Second used Electron45 clipboard.read objects directly for clipboard.write; restoration failed after test text was written. The previous clipboard content was not logged/persisted and could not be restored after process exit. This incident was explicitly reported, not counted green. Both red logs retained. Final harness follows installed electron.d.ts: construct new ClipboardItem objects from all read types before mutation, validate write accepts them, and restore only if clipboard still equals this run's synthetic text. It refuses to substitute an arbitrary nonempty clipboard; only empty or known x×16001 is allowed. Clipboard data is never logged. This does not undo the earlier side effect.

The former Electron paste harness is now unconditionally disabled (exit1), including with --montclip-smoke. No override enables it. Do not rerun it, read clipboard history, or try to restore/clear the current global clipboard. Existing trusted-paste evidence is retained and will not be repeated. Future tests must use controller/event injection or a genuinely isolated clipboard environment. Conditional restoration is not protection against concurrent users.
