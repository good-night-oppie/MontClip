# 分轨录像：每个模块读的是哪条音轨（实测，2026-11-05）

起因：JJ 读代码发现，找歌、音量信号、导出音频窗口都写死了 `-map 0:a:0`（只读第一条音轨），
听写（asr-local.js）没写 `-map`，由 ffmpeg 自己挑。这里先实测，拿证据，再改代码。

## 素材（ffmpeg 现场合成，不用真人素材）

`node synth.cjs <目录>` 生成。每个文件 20 秒，一条灰色画面，三条音轨：

| 轨 | 名字（MKV 的 title / MP4 的 handler_name） | 内容 |
|---|---|---|
| 第 0 轨 | Game | 「游戏声」：220 Hz，一直响 |
| 第 1 轨 | Mic | 「麦克风」：0–5 秒静音，5–15 秒 440 Hz，15–20 秒静音 |
| 第 2 轨 | BGM | 880 Hz，比游戏声小 16 dB |

| 文件 | 各轨声道数 | 哪条轨标了「默认」 |
|---|---|---|
| `three.mkv` / `three.mp4` | 2 / 2 / 2 | 第 0 轨 |
| `three51.mkv` / `three51.mp4` | **6（5.1）** / 1 / 1 | 第 0 轨 |
| `micwide.mkv` / `micwide.mp4` | 1 / **2** / 1 | 第 0 轨 |
| `nodefault.mkv` | 1 / **2** / 1 | 都没标 |
| `nodefault.mp4` | 1 / **2** / 1 | 第 0 轨（MP4 的第一条音轨总是「启用」，去不掉） |
| `micdefault.mkv` / `micdefault.mp4` | 2 / 2 / 2 | **第 1 轨** |
| `single.mp4`（对照） | 只有一条轨：麦克风 | — |

## 怎么判断读到的是哪条轨

- 在服务端（`probe-tracks.cjs`）：直接调用现有模块，把它们实际解码出来的声音拿来看。
  - 找歌：`song-scan.js` 的 `scan()`
  - 音量信号：`signals.js` 的 `loudness()`
  - 导出音频窗口：`audio-window.js` 的 `windowArgs()`，就是导出时 `/api/audio-window` 跑的那条 ffmpeg
  - 听写：`asr-local.js` 的 `transcribe()`。语音引擎换成一个只收样本的替身，ffmpeg 解码是真的
- 判断方法：看 10 秒处的频率（220 / 440 / 880 Hz），再看 0–5 秒和 15–20 秒是不是静音（麦克风的样子）。
  音量信号只有响度，没有频率，就按响度分：游戏声约 −26 dB，BGM 约 −41 dB。
- 在浏览器里（`browser-tracks.cjs`，Chrome 无头模式）：
  - `decodeAudioData`：编辑器画波形、浏览器里找高光、导出窗口失败后的整文件兜底，都走它
  - `<video>` 播放：预览时听到的声音

## 结论

1. 找歌、音量信号、导出、Chrome 解码：**永远读第 0 轨**，跟声道数、默认标记都没关系。
2. 听写跟它们**不一定是同一条轨**。ffmpeg 自己挑轨的规则是：
   - 先挑标了「默认」的轨；
   - 都没标时，才挑声道最多的。
   所以：
   - 5.1 的游戏轨在第 0 轨、又标了默认时，听写也读第 0 轨，大家一致；
   - 默认标记在第 1 轨（`micdefault`），或者都没标、第 1 轨声道最多（`nodefault.mkv`）时，
     听写读第 1 轨，其他模块读第 0 轨。字幕跟找歌、高光、导出出来的声音对不上。
3. 预览播放（Chrome `<video>`）：
   - MKV 读第 0 轨；
   - MP4 读标了默认的那条轨。
   所以 `micdefault.mp4` 预览听到的是麦克风，导出出来的却是游戏声。
4. 主播的声音如果不在第 0 轨（分轨录：麦克风、游戏、BGM 各一条），
   - 找歌、音量、高光、导出读的都不是主播的声音；
   - 现在没有任何地方能改。

### 关于「默认读第 0 轨」对不对

- OBS 录像默认只写第 1 轨（文件里的第 0 轨），所有声音源都混进这一条。
- 每个声音源默认分到全部 6 条轨，所以就算多开了几条轨、没改分配，每条也都是全部声音。
- 只有主播自己在「高级音频属性」里把麦克风、游戏、BGM 分到不同的轨，才会出现「第 0 轨不是她的声音」。
- 所以多数 OBS 录像的第 0 轨是**混好的全部声音**，读第 0 轨不是错的，默认值应该保持第 0 轨。
- 录播姬录的是直播流（FLV），只有一条音轨，不受影响。
- 真正的问题有两个：
  - 听写跟其他模块可能读不同的轨；
  - 主播用了分轨时，没有地方说「我的声音在第几轨」。
- 没有拿真的 OBS 分轨录像实测（不用真人素材）。OBS 写不写「默认」标记、怎么写轨名，是按 OBS 的公开设置说的，没在这台机器上验证。

## 第二步以后（同一个 PR：加了 audioTrack，JJ 审后改成「只管分析」）

- 每个素材条目多了 `audioTrack`，默认 0，存 0 时不写。
- 文件有两条以上音轨时，探测结果里多一个 `audioTracks`：每条轨的声道数、轨名，以及有没有标默认。
- JJ 审过以后，`audioTrack` 只管「分析用的轨」。导出的声音一律用第 0 轨。
  - 原因：第 1 轨常常是全部混音。主播为了找歌、做字幕更准，把轨换成麦克风；如果导出也跟着换，成片里只剩人声，自己还很难发现。

|---|---|---|
| 找歌（song-scan，服务端 / `fablecut_songs`） | 分析 | audioTrack |

| 听写 / 字幕（asr-local；字幕由听写结果生成） | 分析 | audioTrack |

| 高光片段（编辑器 / `fablecut_highlights`） | 分析 | audioTrack |
| 导出混音（`/api/audio-window`，默认值） | 导出的声音 | 0 |
| 波形、按声道拆的音频片段、播放 | 导出的声音 | 0 |
| 响度统一（编辑器 / `fablecut_normalize_audio`） | 处理导出的声音 | 0 |
| 自动压低音乐（编辑器 / `fablecut_auto_duck`） | 处理导出的声音 | 0 |

- 听写现在总是写明 `-map 0:a:<轨>`，不再让 ffmpeg 自己挑轨。
  上面实测表里那三处「**第 1 轨**」，改完后重跑都是第 0 轨，跟其他模块一致了：

  ```
  nodefault.mkv  听写：第 0 轨 游戏声 ~220Hz
  micdefault.mkv 听写：第 0 轨 游戏声 ~219Hz
  micdefault.mp4 听写：第 0 轨 游戏声 ~219Hz
  ```

- 真导出一遍（`e2e-export.cjs`，本机服务 + 无头 Chrome，导出预设 archive；素材 20 秒三轨 MKV，麦克风在 5–15 秒）。
  读导出文件在 2 秒、10 秒、18 秒处的声音：

| audioTrack | 2 秒 | 10 秒 | 18 秒 |
|---|---|---|---|
| 0 | −21.1 dB，220 Hz（游戏） | −21.1 dB，220 Hz（游戏） | −21.1 dB，220 Hz（游戏） |
| 1 | −21.1 dB，220 Hz（游戏） | −21.1 dB，220 Hz（游戏） | −21.1 dB，220 Hz（游戏） |

  选了第 1 轨（麦克风），导出的仍然是第 0 轨。JJ 审之前那一版，导出会跟着换，10 秒处是 440 Hz，2 秒和 18 秒是静音。
  过零次数是按 0.5 秒数的，seek 边上会少几次，所以 220 Hz 读到的是 190–218 次。

### 换轨以后自动重做

- 找歌和音量：保存以后，在后台按新轨重新读，不用点。
  - 项目里原来存着找歌结果（`fablecut_songs` 存的）的话，读完会按新轨写回去。
- 字幕：
  - 每条字幕现在都记着它生成时的文字（`props.captionMade`）。
  - 判断「改过」的规则：没有这个记录（这次以前做的字幕）、文字跟记录不一样、或者没有逐字时间（从 SRT / VTT 导入的），都算改过。
  - 以前做的字幕分不出有没有改过，所以一律当成改过，不会自动覆盖。
  - 没改过：自动按新轨听写，再按原来的样式重做字幕。重做算一步，可以撤销。
  - 改过：不动，弹出提示，带〔按这条轨重做字幕〕；素材信息里的选择下面也有这个按钮。点了就替换字幕，算一步，可以撤销。

### 还没覆盖的

- 编辑器**预览播放**、波形、导出都是第 0 轨，这是这次定下的规则。
  - 唯一的例外：MP4 预览时，Chrome 会放标了默认的那条轨。
  - 要改，得让代理文件明确用第 0 轨，另开任务。
- 「导出单独某条轨」：按 JJ 的意见，以后在导出设置里另加选项，这次不做。
- 超过 1 小时的录像，选了非 0 轨以后，编辑器里的节拍、静音、高光没法整段从服务端读，这时不会退回去读第 0 轨。
- 「字幕没改过 → 自动按新轨重做」这条路，要先在本机听写。这台机器没装听写模型，所以没在真编辑器里跑过；只用测试锁住了判断规则和调用。

## VV 复看后的改动（head cff8803 之后）

### 导入 MP4 时多余的音轨被删掉了（main 上原来就有的 bug）

- **原因：** `import-url.js` 给 mp4 / mov / m4v 做 faststart 时用的是 `-i file -c copy`，没写 `-map`。ffmpeg 默认每类流只留一条，三轨 MP4 导入后只剩 1 条音轨。
- **改法：** 改成 `-map 0 -map -0:d -map -0:t -c copy`。
  - 字幕、章节一起保留；
  - 数据流（MOV 的时间码轨这类）和附件不要：MP4 写不了大多数这类流，`-c copy` 碰到它会让整次 faststart 失败。
- **手动对照：** 三轨 MP4，旧参数处理后剩 1 条音轨，新参数处理后还是 3 条。
- **其他导入路径：**
  - 上传、网址导入、MCP 的网址导入：都走这一个函数，一起修好了。
  - 桌面版用系统文件框导入：也是走 `/api/upload`。
  - FLV 转封装：`prepare-media.js` 本来就写明 `-map 0:v:0 -map 0:a:0?`，多于一条音轨时直接拒绝（`FLV_STREAMS_UNSUPPORTED`），不会悄悄删轨。
  - MCP 导入本机文件：只复制，不做 faststart。
- **测试：** 三轨 MP4 走上传、走带 ticket 的上传（桌面导入用的就是这条），之后都还是 3 条音轨，`audioTracks.length===3`。带时间码数据流的 MOV，faststart 能成功，3 条音轨都在。
