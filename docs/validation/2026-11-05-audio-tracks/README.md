# 分轨录像：每个模块读的是哪条音轨（实测，2026-11-05）

起因：JJ 读代码发现，找歌、音量信号、导出音频窗口都写死了 `-map 0:a:0`（只读第一条音轨），
听写（asr-local.js）没写 `-map`，由 ffmpeg 自己挑。这里先实测，拿证据，再改代码。

## 素材（ffmpeg 现场合成，不用真人素材）

`node synth.cjs <目录>` 生成。每个文件 20 秒，一条灰色画面，三条音轨：

| 轨 | 名字（MKV 的 title / MP4 的 handler_name） | 内容 |
|---|---|---|
| 第 0 轨 | Game | 「游戏声」：220 Hz，一直响 |
| 第 1 轨 | Mic | 「麦克风」：0–5 秒静音，5–15 秒 440 Hz，15–20 秒静音 |
| 第 2 轨 | BGM | 880 Hz，比游戏声小 16 dB |

| 文件 | 各轨声道数 | 哪条轨标了「默认」 |
|---|---|---|
| `three.mkv` / `three.mp4` | 2 / 2 / 2 | 第 0 轨 |
| `three51.mkv` / `three51.mp4` | **6（5.1）** / 1 / 1 | 第 0 轨 |
| `micwide.mkv` / `micwide.mp4` | 1 / **2** / 1 | 第 0 轨 |
| `nodefault.mkv` | 1 / **2** / 1 | 都没标 |
| `nodefault.mp4` | 1 / **2** / 1 | 第 0 轨（MP4 的第一条音轨总是「启用」，去不掉） |
| `micdefault.mkv` / `micdefault.mp4` | 2 / 2 / 2 | **第 1 轨** |
| `single.mp4`（对照） | 只有一条轨：麦克风 | — |

## 怎么判断读到的是哪条轨

- 在服务端（`probe-tracks.cjs`）：直接调用现有模块，把它们实际解码出来的声音拿来看。
  - 找歌：`song-scan.js` 的 `scan()`
  - 音量信号：`signals.js` 的 `loudness()`
  - 导出音频窗口：`audio-window.js` 的 `windowArgs()`，就是导出时 `/api/audio-window` 跑的那条 ffmpeg
  - 听写：`asr-local.js` 的 `transcribe()`。语音引擎换成一个只收样本的替身，ffmpeg 解码是真的
- 判断方法：看 10 秒处的频率（220 / 440 / 880 Hz），再看 0–5 秒和 15–20 秒是不是静音（麦克风的样子）。
  音量信号只有响度，没有频率，就按响度分：游戏声约 −26 dB，BGM 约 −41 dB。
- 在浏览器里（`browser-tracks.cjs`，Chrome 无头模式）：
  - `decodeAudioData`：编辑器画波形、浏览器里找高光、导出窗口失败后的整文件兜底，都走它
  - `<video>` 播放：预览时听到的声音

## 结论

1. 找歌、音量信号、导出、Chrome 解码：**永远读第 0 轨**，跟声道数、默认标记都没关系。
2. 听写跟它们**不一定是同一条轨**。ffmpeg 自己挑轨的规则是：
   - 先挑标了「默认」的轨；
   - 都没标时，才挑声道最多的。
   所以：
   - 5.1 的游戏轨在第 0 轨、又标了默认时，听写也读第 0 轨，大家一致；
   - 默认标记在第 1 轨（`micdefault`），或者都没标、第 1 轨声道最多（`nodefault.mkv`）时，
     听写读第 1 轨，其他模块读第 0 轨。字幕跟找歌、高光、导出出来的声音对不上。
3. 预览播放（Chrome `<video>`）：
   - MKV 读第 0 轨；
   - MP4 读标了默认的那条轨。
   所以 `micdefault.mp4` 预览听到的是麦克风，导出出来的却是游戏声。
4. 主播的声音如果不在第 0 轨（分轨录：麦克风、游戏、BGM 各一条），
   - 找歌、音量、高光、导出读的都不是主播的声音；
   - 现在没有任何地方能改。

### 关于「默认读第 0 轨」对不对

- OBS 录像默认只写第 1 轨（文件里的第 0 轨），所有声音源都混进这一条。
- 每个声音源默认分到全部 6 条轨，所以就算多开了几条轨、没改分配，每条也都是全部声音。
- 只有主播自己在「高级音频属性」里把麦克风、游戏、BGM 分到不同的轨，才会出现「第 0 轨不是她的声音」。
- 所以多数 OBS 录像的第 0 轨是**混好的全部声音**，读第 0 轨不是错的，默认值应该保持第 0 轨。
- 录播姬录的是直播流（FLV），只有一条音轨，不受影响。
- 真正的问题有两个：
  - 听写跟其他模块可能读不同的轨；
  - 主播用了分轨时，没有地方说「我的声音在第几轨」。
- 没有拿真的 OBS 分轨录像实测（不用真人素材）。OBS 写不写「默认」标记、怎么写轨名，是按 OBS 的公开设置说的，没在这台机器上验证。

## 第二步以后（同一个 PR：加了 audioTrack）

- 每个素材条目多了 `audioTrack`（默认 0，存 0 时不写）。
- 有两条以上音轨的文件，探测结果里多了 `audioTracks`：每条轨的声道数、轨名、是否标了默认。
- 下面这些都读同一条轨（`MediaLib.audioTrackOf`）：
  - 找歌、音量信号、导出音频窗口、听写；
  - MCP 里的静音、节拍、响度统一、自动压低音乐（`streamClipAudio`）。
- 听写现在总是写明 `-map 0:a:<轨>`，不再让 ffmpeg 自己挑。
  上表那三个「**第 1 轨**」，改完以后重跑都是第 0 轨，跟其他模块一致：

  ```
  nodefault.mkv  听写：第 0 轨 游戏声 ~220Hz
  micdefault.mkv 听写：第 0 轨 游戏声 ~219Hz
  micdefault.mp4 听写：第 0 轨 游戏声 ~219Hz
  ```

- 真导出一遍（`e2e-export.cjs`）：
  - 用的是本机服务 + 无头 Chrome，导出预设 archive；
  - 素材是 20 秒三轨 MKV，麦克风在 5–15 秒；
  - 读出导出文件在 2 秒、10 秒、18 秒处的声音：

| audioTrack | 2 秒 | 10 秒 | 18 秒 |
|---|---|---|---|
| 0 | −21.1 dB，220 Hz（游戏） | −21.1 dB，220 Hz（游戏） | −21.1 dB，220 Hz（游戏） |
| 1 | 静音 | −21.1 dB，440 Hz（麦克风） | 静音 |

（过零次数数的是 0.5 秒里的，seek 边上会少几次；220 Hz 读到 190–218 次，440 Hz 读到 379 次。）

### 还没覆盖的（说清楚，不算在这次里）

- 编辑器里的**预览播放**，还是浏览器自己挑的轨：
  - MKV 是第 0 轨；
  - MP4 是标了默认的那条。
  - 要改，得让代理文件（proxy.js 现在写死 `0:a:0?`）按轨来做，另开任务。
- 波形、浏览器里的高光会跟着选的轨走：
  - 选了第 1 轨以后，它们从服务端按轨解码；
  - 超过 1 小时的录像，选了非 0 轨就不画波形，不会退回去读第 0 轨。
- `denoise.js`（降噪）还读第 0 轨。
