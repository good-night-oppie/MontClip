证据等级采用 S-r2 第 0 节的定义：

- **A**：直接观察（字节、反汇编、反编译、文件哈希）。都是静态的，不等于运行时确实这样走。
- **H**：历史缓存存在证据。只能说明某个缓存文件现在存在、哈希是多少，不能说明它是下载来的、被加载过，或由哪个操作触发。
- **B**：推断。
- **U**：未知。

S-r1 只有自己的四种标注。凡是 S-r2 对同一件事给了等级，下面一律用 S-r2 的；只有 S-r1 提到的，按「静态读出的结构 = B，未知 = U」折算，并注明是折算。

## Gemini 说错或不适用的地方

1. **CapCut 自动字幕走云端，不是本地模型。**
   - 证据：S-r2 §1 第 4 条，A。字幕流程是「上传音频片段 → 提交 → 查询或推送」，这条路径上没有本地模型加载；服务端用什么模型是 U。S-ext 也把自动字幕列为「预期需要联网」，但那是预期，U。
   - 本地语音引擎确实存在，但静态上**只找到**它接在素材搜索索引上的调用点（S-r2 §1 第 5 条，A：调用点）。S-r2 明确说没有证明这是它唯一的用途（U）。本文初版写的「本地语音识别只给素材搜索建索引用」说过头了，这里更正。
   - 结论不变：MontClip 主人要求本地听写，所以「本地 ASR 能完成字幕」要靠我们自己实测，不能拿 CapCut 当先例。
2. **生成类模型客户端不写死。**
   - 证据：S-r2 §1 第 9 条，A。生成和 Agent 视频工具把模型字段原样放进请求，工具描述来自远端配置。界面上的生成模型品牌文案在扫描范围内没有直接的代码引用，只算界面文案；实际请求的模型标识是 U。
   - 所以 Gemini 列出的 Seedance、Seedream 等名字不能当作 CapCut 实际在用的证据。
3. **人机不是两条撤销栈。** MontClip（沿用 FableCut）是一条共享撤销栈：Agent 每次改动是其中独立的一步，另有版本快照。Gemini 说的「区分人机 Undo 栈」不准确。
4. **中文只有句级时间。** Gemini 的逐词动态字幕（word-pop、karaoke、按 WhisperX 词级时间切）不适用于中文听写。现有规则是：没有真实词时间就不做逐词动画（R06）。
5. **「隐式注入 UI 上下文」与我们的外发规则冲突。** MontClip 要求发送前审阅完整外发内容（R05、N12）。播放头、选区这类上下文可以自动带上，但必须作为可见、可删的引用芯片出现在审阅里，不能藏在看不见的 system 块中。
6. **Python 侧车被否决。** SenseVoice-Small 和 WhisperX 的 Python 版本不能用（R08）。只有非 Python 的实现（ONNX，例如 sherpa-onnx 的 wasm 或 Node 版本）才能进入实测候选。

## 目标架构

```
导入素材 ──► 本地素材索引（后台，可取消，无网络、无 Python）
               └─ analysis/index/<sha256>.json：响度曲线、静音段、镜头切点、节拍、
                  句级文稿引用；有弹幕时另存
前台对话 ──► 引用芯片（项目、句子、片段、区间 + 播放头、选区）
               ──► 发送前完整审阅（外发什么，看什么）
               ──► 模型回复 ──► 提案卡（高光 / 保留句子 / 包装）
                                   ├─ 跳转：只在本地，不调模型
                                   └─ 应用：校验修订号 → 分步补丁 → 每步独立撤销
```
