## Gemini 说错或不适用的地方

1. **CapCut 自动字幕走云端，不是本地模型。** 本地语音识别只给素材搜索建索引用（SPEC §3）。MontClip 主人要求本地听写，所以「本地 ASR 能完成字幕」这件事要靠我们自己实测，不能拿 CapCut 当先例。
2. **生成类模型客户端不写死。** CapCut 的可选模型列表来自远端配置，界面上的品牌文案不代表客户端绑定了这个模型（SPEC §3）。Gemini 列出的 Seedance、Seedream 等名字不能当作 CapCut 实际在用的证据。
3. **人机不是两条撤销栈。** MontClip（沿用 FableCut）是一条共享撤销栈：Agent 每次改动是其中独立的一步，另有版本快照。Gemini 说的「区分人机 Undo 栈」不准确。
4. **中文只有句级时间。** Gemini 的逐词动态字幕（word-pop、karaoke、按 WhisperX 词级时间切）不适用于中文听写。现有规则是：没有真实词时间就不做逐词动画（R06）。
5. **「隐式注入 UI 上下文」与我们的外发规则冲突。** MontClip 要求发送前审阅完整外发内容（R05、N12）。播放头、选区这类上下文可以自动带上，但必须作为可见、可删的引用芯片出现在审阅里，不能藏在看不见的 system 块中。
6. **Python 侧车被否决。** SenseVoice-Small 和 WhisperX 的 Python 版本不能用（R08）。只有非 Python 的实现（ONNX，例如 sherpa-onnx 的 wasm 或 Node 版本）才能进入实测候选。

## 目标架构

```
导入素材 ──► 本地素材索引（后台，可取消，无网络、无 Python）
               └─ analysis/index/<sha256>.json：响度曲线、静音段、镜头切点、节拍、
                  句级文稿引用；有弹幕时另存
前台对话 ──► 引用芯片（项目、句子、片段、区间 + 播放头、选区）
               ──► 发送前完整审阅（外发什么，看什么）
               ──► 模型回复 ──► 提案卡（高光 / 保留句子 / 包装）
                                   ├─ 跳转：只在本地，不调模型
                                   └─ 应用：校验修订号 → 分步补丁 → 每步独立撤销
```

## 分期（每期一个独立 PR，先写测试，送审规矩照旧）

| 期 | 内容 | 依赖 | 验收要点 |
|---|---|---|---|
| P1 | **本地素材索引**：导入后后台运行；内容 SHA-256 作身份；用现有 silence、beats、analyze 和响度测量；状态分排队、进行中、就绪、失败；REST 和 MCP 可读 | main | 断网可用；同一内容改名后不重算；内容改了才重算；取消和失败不影响项目；中文路径 |
| P2 | **高光候选卡（只用本地信号）**：从索引和句级文稿生成候选，附理由；「跳转」只在本地；「应用」走区间引擎、一步撤销 | P1，#26 | 零模型也能用；每条理由可追溯到信号；没有候选时显示明确的空状态（R02、R04） |
| P3 | **对话里用索引**：模型拿到的是候选摘要（文字），不是整片；播放头和选区作为可删芯片；应用时校验修订号 | P2，#26 | 审阅里能看到每一项外发内容；修订号过期拒绝；一个提案多步、每步可撤销 |
| P4 | **任务 → 模型本地路由**和快捷胶囊（选中片段后出现相关动作） | P3 | 覆盖顺序「指定 > 默认」；不远端下发；未配置时手动功能照常 |
| P5 | **SVG 模板 CSS 变量调参**（不调模型）和随包模型清单（SHA-256，首用状态） | P1 | 调参只改本地文件且可撤销；模型坏哈希时准确报错，不外连 |
| 研究 | **非 Python 中文 ASR 实测**：sherpa-onnx（wasm 或 Node）+ SenseVoice，对比当前 Whisper q8 | Rea 的样本 | 中文字错率、时间戳越界、静音幻听三项过关才进入候选；只报实测数字 |

## 需要主人决定

1. 分期顺序：建议先做 P1。它只依赖 main，后面每期都要用。
2. ASR 研究是否立项：sherpa-onnx 带原生或 wasm 组件。「零依赖」只针对编辑器，桌面版已带 Electron；这个依赖要单独评估许可证和包体积。
3. 是否允许 Agent 在开发中把设计问题发给 Gemini 咨询：发送就是外发，需要确定用哪个浏览器账户，以及哪些内容可以发（建议只发脱敏后的设计问题，不发素材、密钥或私人路径）。

本文是设计决定，没有任何代码改动和测试结论。
