# SOP v3.1 第 13 条：修复先实跑

日期：2026-11-08。负责人：BB。状态：主人已决定；QQ 核读、JJ 措辞已通过；入库终审绑定当前 head。

## 决定

> 13. 修复先实跑。修复人把改动交给试剪的人、主播或初审之前，必须自己在真实环境把主播的完整流程走一遍；单元测试、smoke 测试通过都不算数。
>   - 适用范围：改动会让主播看到、点到或听到不同结果的（界面、安装、导入、剪辑、导出、听写、联网功能），一律要实跑。只改文档、CI、测试的，在 PR 里写「实跑：不适用，原因：…」。
>   - 环境：用主播实际用的系统（Windows 11）。影响 Windows 桌面版的，在 Win11 测试电脑上跑；影响插件的，在 Win11 的 Cindy 里跑，europa 上跑的只算辅助。只在 Linux CI 或开发机上跑过的，写「没在 Windows 实跑」，不当作实跑。涉及安装、首次使用的，新建临时用户目录或数据目录，开发机上已经装好的不算；不准删除真实数据。要动已经装好的环境，先整包备份，跑完恢复。
>   - 流程：从主播第一下点击走到她拿到结果；中途离开再回到页面，也要走一次。
>   - 记录：PR 里贴「主播视角步骤记录」——实跑的是哪个 commit、在哪台机器、点了什么、看到什么字、每一步等了多久、截图或录屏。之后再推了改动主播流程的提交，就重跑；只改测试或文档的，写「沿用 <sha> 的实跑」。贴进 PR 前先打码：不放密钥、账号信息、观众昵称、Windows 用户名和本机完整路径；画面只用合成的或有授权的素材，不用主播的真实录像。
>   - 联网：涉及联网功能的，实跑时要看到「发送前先显示内容和目的地」那一步，也要试一次在提示上点取消，确认取消时什么都没发出去。
>   - 界面状态：凡是显示「已装好 / 缺失 / 去装」这类状态的，必须和真正执行时用的是同一个判断；实跑时核对状态和结果一致。
>   - 没亲眼看到的承诺不写：提示里承诺的事（后台进行、完成会提醒等），实跑时必须亲眼看到发生，否则删掉这句。
>   - 没有实跑记录的 PR，初审直接退回，不转给试剪的人测；QQ 终审也核这份记录，没跑就判「要改」。例外只认 QQ 在当前 head 上写的「SOP 例外已核验：第 13 条」，并写清原因和用什么代替了实跑；head 一变就失效；动到联网、外发或密钥的改动不给例外。
