## 对合并版的一处修正（附出处）

合并版写的是「1b 等调参素材授权谈下来再做」。主人之前已经定过两条，1b 的调参不用等：

1. **未授权的公开回放可以本地调参。** 主人原话（2026-11-03 08:10 UTC，主人直接发给 Deja 的消息）：「没授权的公开回放照旧可以用来本地调参，只限本机和 europa，不分发、不进仓库、不训练发布模型。」
2. **CC BY-NC-SA 数据集也拿来调优。** 主人原话（2026-11-02 23:22 UTC，经 JJ 转达，宿主核实是主人本人的话）：「不是要上架卖的 这也是开源工具。」「（QVHighlights、AntHighlight、KuaiLive-M3）也拿来调优。告诉 DD 和 Deja」。JJ 当时转达的背景是：调研 v1 写的「MontClip 要上架卖」是错的，MontClip 是开源工具；原先「NC 数据集一律不调参」的决定作废。

**NC 许可的风险，主人是知情的。** 主人纠正的正是「要上架卖」这个前提，在这个前提下决定用 NC 数据调优。用这些数据调出来的是写进代码的阈值和权重，会随 MontClip 一起发布；数据本身、转出来的标注和训练出来的模型，都不发布。

**边界。**
- 数据原文件和转出的标注，只放本机、europa 的 `~/montclip-golden`，或者主人的私有 S3。不进 git，不换许可证再发布。ADR 和评测报告里写明来源和署名。
- 不训练对外发布的模型。如果以后要用这些数据训练一个随产品发布的模型，或者 MontClip 要商用，这一条要重新请主人决定。
- 素材台账的授权一栏照实写：公开回放写「公开回放，未获本人授权，主人批准仅用于本地调参」；NC 数据集写许可证名和来源。
- 拿到主播本人授权的素材以后，加进来做对照。弹幕密度、高能进度条、礼物仍然不能当真值。

- 每个特性先拆成能单独测试、单独合并的小 PR，先写测试，测试用合成素材。
- 新的主播可见文字由 JJ 定稿，Rea 逐字核对；交互由 VV 确认；QQ 和 Rea 审完由 QQ 合并。
