# ADR 2026-11-02: which encoder makes H.264 (MP4) exports

Status: decided by the owner on 2026-11-02 (relayed by Deja: 「按这个来（A + 可选本机
FFmpeg）」); implemented in PR #28 (draft). Not legal advice; the patent points below
should be confirmed by someone who knows software licensing before a public release.

## Context

MontClip runs only the FFmpeg it ships (`ffmpeg-path.js`), and ships only an LGPL
build (no GPL components: team rule, MIT project). The LGPL build has no libx264, so
without something else there is no software H.264 encoder: on a computer without a
usable graphics-card encoder, MP4 export failed (`Unknown encoder 'libx264'`).

## Options (Deja, `2026-11-02-MontClip-导出MP4编码器选择.md`)

| | Option | Quality | Licence / patents | What the user does |
|---|---|---|---|---|
| **A** | Windows' own encoder (`h264_mf`, Media Foundation) + graphics-card encoders (NVENC / Quick Sync / AMF) | graphics-card encoders good; `h264_mf` software MFT usable, a little softer than x264 at the same size | the encoder comes with Windows or the graphics driver; MontClip does not distribute it | nothing; Windows "N" editions need the Media Feature Pack |
| B | openh264 inside the packaged FFmpeg | weaker than x264 | Cisco only covers its own published binaries; a statically built copy is not covered → patent risk | nothing |
| C | download Cisco's openh264 on first export | as B | patents carried by Cisco | must go online once; breaks "offline by default"; the current FFmpeg cannot load it that way |
| D | a GPL FFmpeg with x264 in the package | best | GPL obligations; breaks the LGPL-only rule | nothing |

## Decision

**A, plus an optional local FFmpeg.**

1. H.264 export uses, in this order: a graphics-card encoder (NVENC, Quick Sync,
   AMF, VideoToolbox — the existing 2-frame probe decides which answer), then
   Windows' `h264_mf`. An encoder with a minimum frame size (NVENC: 145×49) gives
   way when the output is smaller.
2. In Settings (desktop) the user may choose an FFmpeg already on their computer
   that has libx264. When they have chosen one and it checks out, H.264 exports
   use its libx264 first: that is what they asked for.
3. With no H.264 encoder at all, export refuses before rendering and says why in
   plain words; on Windows without Media Foundation (an "N" edition) it points to
   the Media Feature Pack. It never pretends an export succeeded.
4. The package contains only the LGPL build. MontClip does not distribute x264
   and downloads nothing.

Reasons: only LGPL in the package; no x264/openh264 distributed by MontClip; offline
by default; most streamers' computers have a graphics-card encoder; the rest get
Windows' encoder; those who want x264 can use their own FFmpeg.

## The local FFmpeg (rules)

- Only the absolute path the user picks in the main process's file dialog
  (`montclip:ffmpeg:choose`). Never PATH, never a guess, never a path from the page.
- Checked before use: `-version` and `-encoders` with argument arrays, no shell; it
  must list libx264. The main process stores `{version:1, path}` in
  `userData/external-ffmpeg.json`; the server reads it
  (`MONTCLIP_EXTERNAL_FFMPEG_SETTINGS`) and checks again whenever the setting or the
  file changes (`external-ffmpeg.js`).
- Used only to encode an H.264 export (libx264, including raw encoding profiles that
  use libx264). Preview, decoding, probing, proxies and every other export use the
  bundled FFmpeg.
- If the file disappears or the check fails, exports fall back to point 1 and the
  export notes / Settings say why.

## Open items

- **The pinned BtbN LGPL build itself links libopenh264** (`--enable-libopenh264`).
  MontClip never selects that encoder, but the code is inside the shipped
  `ffmpeg(.exe)`, which conflicts with "do not distribute openh264". A build without
  it (BtbN variant, or our own LGPL build) still has to be chosen. release-check
  prints a warning until then.
- macOS: the same idea with VideoToolbox, when the macOS build is made.
- Measured quality and speed: `docs/validation/2026-11-02-h264/` (synthetic source,
  one Windows laptop). VV is to look at real exports.
