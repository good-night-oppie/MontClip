## Strings

The parts use i18next as Cindy does (namespace `common`, English fallback). Cindy's whole common.json is 2 MB per
language, so `vendor-cindy.cjs` keeps the strings these files can ask for (`cindy-strings.json`, 343 zh-CN / 352 en;
the 9 more in English are `_one` plural forms). It reads the string literals with TypeScript's parser: a regex
mispaired quotes and missed keys. `montclip-strings.json` holds MontClip's words where Cindy's do not fit; for now only
the mode capsule (the four modes, as in the pane today). The smoke checks that no part asks for a missing key.

## The bundle

The parts are in `cindy-official.js`, as `window.MontClipCindyParts`; the pane does not show them yet. The bundle grows
from 221 KB to 608 KB. Every npm package in it is listed in `BUNDLED-PACKAGES.json` (written by the build), with its
version and full license in `BUNDLED-LICENSES.json` and `THIRD-PARTY-NOTICES.txt` (written by `licenses.cjs`).
react-remove-scroll-bar 2.3.8 ships no license file: its MIT text comes from its repository (commit recorded).

## Cindy's styles (the second change)

`cindy-parts.css` (loaded before `style.css`) is generated by `agent-ui/styles.cjs` from files copied unchanged at 43001ea
(`tailwind.config.ts`, `styles/generated/tokens.css`, `components/ui/button.css`, and `themes/colors.ts`,
`theme-service.ts`, `builtin/cindy-dark.ts`, which run only at build time):

- **Tailwind 3.4.19** with Cindy's config, over the parts' own files, with its preflight (the reset of every element the parts
  count on: a button has no face of its own; without it, buttons and fields showed the browser's white face). Its html / body
  rules are left out.
- **Cindy's colours**: its theme code turns cindy-dark into 570 CSS variables, as Cindy does when it applies a theme.
- **Every rule applies inside the parts only** (VV on f3df7db; Deja, 2026-11-04): Cindy's variables, preflight, the Tailwind
  utilities, tokens.css and button.css. Each selector is put under, or on, the elements the parts live in: the box a part is
  rendered in (`data-cindy-parts`, set by `parts.tsx`) and what they open over the page (Radix popovers and tooltips, Cindy's
  MorphPopover panel, the confirm dialog and its scrim `.modal-scrim`). Nothing is set on `:root`, and no class of Cindy's
  (`.hidden`, `.grid`, `.block`, `.fixed`, `.filter`, `.sr-only`…) reaches an element of MontClip's.
- **MontClip's variable names stay MontClip's**: a name MontClip's page uses or sets (style.css, app.js, index.html, pane.tsx)
  that Cindy has too is written `--cindy-<name>` in the file, everywhere Cindy's rules set or read it. Today: `--accent`,
  `--border`, `--muted`, `--chat-input-bg`, `--chat-input-border`, `--chat-input-border-focus`, `--send-btn-bg`,
  `--send-btn-hover-bg`, `--send-btn-icon`, `--send-btn-pressed-bg`. Before this, `--muted` (Cindy's HSL numbers, not a colour)
  was on `:root`, so MontClip's ten `color: var(--muted, #9a9aaa)` lost their grey and turned to the text white: the export
  dialog, the batch list, the export queue and the plan list (VV measured rgb(154,154,170) → rgb(215,215,220)). No copied
  part reads one of these names from JavaScript or an inline style.
- **MontClip's colours** (`agent-ui/montclip-theme.css`, last): the accent #7b6cff for the focus ring, 自动 and the main buttons
  (Cindy's white main button becomes MontClip purple; a gradient cannot go in a background colour, so MontClip's own
  `.btn.primary` keeps the gradient); Yolo in MontClip's red #e5484d, as its bar. Cindy's neutrals stay. Only the dark theme:
  MontClip has no light one.
- Checked: `test/cindy-parts-styles.test.js` (generated from what; every selector inside the parts; no variable name of
  MontClip's set or read; MontClip's colours last) and `desktop/cindy-parts-smoke.cjs`: MontClip's own controls, and VV's
  grey texts (`.xq-sub`, `.dlv-wh-in span`, `.cindy-plan-what`), measure the same with the file on and off; no Cindy variable on
  the page's root; a part's button has no browser face; the focus ring and Yolo in MontClip's colours. Screenshots: offscreen.

## Thinking and work times in Chinese (VV on f3df7db)

- ThinkingCard's title while it thinks is the word "Thinking" in Cindy's JSX, not a string, so a Chinese window showed it in
  English. The copied file is not changed: when the bundle is built, that piece (and "Thinking hidden") is replaced with a
  t() call (`cindy-resolve.cjs` PATCHES; each piece must be in the file exactly once, or the build stops). The words are in
  `montclip-strings.json`: 「正在想」 / Thinking, 「这段思考没有显示」 / Thinking hidden (new, for JJ).
- Cindy says how long in its shorthand in every language (58s, 1m 29s). A stand-in for `lib/sessionDurationFormat` says it in
  words in Chinese (`stand-ins/durationWords.cjs`: 58 秒, 1 分 29 秒, 2 分, 1 小时 5 分) and is Cindy's own formatDuration in
  English. So: 「正在想… 1 分 29 秒」, 「已工作 58 秒」, 「思考 58 秒」.
- The 「…」 is the card's own three animated dots. Their rules are in Cindy's `styles/globals.css` (its whole app's rules),
  now copied unchanged too; `styles.cjs` takes from it only the `.thinking-dot` rules, their `thinking-dot-wave` animation
  and the reduced-motion rule that stops it. Before, the dots had no size, so the title read 「正在想 1 分 29 秒」.
- Tailwind's license: its preflight and rules ship in that file (`STYLE-PACKAGES.json` → `BUNDLED-LICENSES.json`,
  `THIRD-PARTY-NOTICES.txt`).
