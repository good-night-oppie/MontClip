每一环做三件事：接的时候写承接，做完把证据写在单上，再用伙伴消息把链接、状态和「下一步是谁」发给下一个人。超时了由第 4 条写明的接手人直接接，不等第二次提醒。

1. 北极星：让剪自己直播的主播下播后不用命令行，用更少的主动操作时间，从自己的录像得到第一条愿意发的切片；画质、音画同步、隐私和每一步的决定权不打折，做不到的如实说。优先做导入、找高光、改头尾、剪掉不要的、同步导出和打码，先做不带弹幕的高光切片。衡量：同一主播、可比的录像，从选文件夹到她确认导出第一条满意切片的主动操作分钟数，记下卡住的步骤；她同意才记，没测就说没测。小样本只算个案，合成素材和真人素材分开，准确率只用有授权的标注素材。
2. 铁律：见 skills/montclip-clip/SKILL.md 铁律 1–6 原文。
3. 联网和隐私：MontClip 可以联网，没有默认不联网的约定；但联网只发生在主播自己打开的功能里，由她操作触发并同意，不在后台联网，不自动上报，不采集遥测。任何外发之前先显示内容和目的地，由她决定；选了「都批准」或 Yolo 也照样显示。录像和弹幕默认在本机处理；账号信息不外发；她配的服务密钥只用于她选的那个服务，密钥只放在软件后台，不进日志和报告；团队自己的密钥只用 1Password 引用；对外分享前先打码。新增联网或外发路径，单独写 ADR 并经 QQ 核验。
4. 责任链和时限（每行：环节：谁，多久 → 超时谁接）：
   - 写单、验收标准、建议优先级：JJ → Deja 兜底。
   - 产品决定：PG，4 小时 → 按 JJ 的建议优先级暂行，Deja 先排队，PG 回来可以改。
   - 排期、指定唯一的实现负责人、定合并顺序：Deja，1 小时 → QQ 代排。
   - 排障：Cindy。查错的活先只读排查，交根因报告和能复现的红测，写明哪些是自己复现的、哪些只是执行任务报告的 → 排不出根因时如实写卡在哪，由 Deja 改派。
   - 承接和修复：实现负责人，由 Deja 在 Deja、BB、Cindy 里指定一个，查错和排障类的优先给 Cindy；承接 1 小时、修复 3 小时 → Deja 改派给另外两人之一；实现负责人是 Deja 自己时 QQ 代排。
   - 自动初筛：ReviewInbox，PR 每个新 head 上发一条 COMMENT（通过 / 要改 / 需要讨论），不算批准，也不挡初审和终审 → 它出故障时不等它，照常叫初审和终审；App 的问题交 BB 排查。
   - 初审：媒体类 Rea，界面类 DD 或 VV，2 小时 → QQ 直接终审，不等初审。
   - 终审、批准、合并：QQ，复审 2 小时、合并 6 小时 → 直接报主人，同时 PG 先做不含批准的预审；批准和合并没有人能代，仍等 QQ。
   - 写明 europa 插件包 sha256 和引擎对应的 main 提交号：DD，合并后 1 小时 → Deja 代写。
   - 复测、关单：Video，承接 1 小时 → DD 代测。
   - 交付跟进：Cindy 的例行任务跟各个 PR 和任务的状态，记进 Todo；状态没变不重复催办。跟的是别人的单时，不推送、不送审、不安装插件、不重启、不部署；遇到要主人决定的事（权限确认卡、安装确认、代码推到哪个仓库）不代答，报主人并写明在哪张卡上决定。CI 通过、合成素材测试通过都不算实包验收，验收看 Win11 实跑和 europa 复测。
   - 巡检和督查：BB 持有，每 5 分钟一次，只在状态变化时唤醒 → QQ 兜底。

   草稿 2 小时提醒、3 小时交 Deja、24 小时经 Deja 确认后关闭。长周期工作每 1–2 小时报一次进度，赶不上要在到期前说。
5. 送审：一次送审写三处，三处的读者不同，少一处就会卡在那一环。
   - PR 正文，给 lint 和审查人读：第一行「<伙伴名> 请审」，写这次请谁审，一般是 QQ，QQ 自己写的 PR 写 DD，审查人不能是负责人自己；第二行「负责人：<伙伴名>」；写明对应的 Issue、改动、复现、测试（写数字或「没跑」加原因）、依赖；按改动的文件补写音画同步和外发。正文不会通知任何人，路由不读正文。
   - Issue，给巡检 montclip-rsi 读：新增一条 RSI-EVIDENCE v1，kind: implementation，带 HTTPS 链接和 40 位完整 head。巡检只读 Issue，不读 PR，没有这条它会把这张单报成缺实现证据。head 变了就新增一条，不改旧的，编辑过的记录巡检不认。
   - PR 评论，用来叫审查人：新增一条评论，第一个非空行以 @<伙伴名>OppieXYZ 开头，空格后写要对方做的事，例：「@QQOppieXYZ 请终审，重点看导出路径」；同一行可以连着叫几个人。初审媒体类叫 Rea，界面类叫 DD 或 VV，终审叫 QQ，QQ 自己写的 PR 叫 DD，初审和终审可以同时叫。ReviewInbox 会先在当前 head 上自动初筛，它只发 COMMENT，不算批准。

   「Oppie GitHub 明确提及路由」只转发这样的评论：发在 MontClip、MontClip-Cindy、montclip-rsi 三个仓库，由名单里有写权限的真人账号发出，@ 不在引用和代码块里。App 和机器人账号发的不转；发出后不要编辑，要改就新增一条。它转过去的只是一条带链接和 head 的固定通知，对方自己去读原评论；它不评审、不批准、不合并，也不催办，最快 5 分钟一轮。「已排队」不等于对方承接，承接看对方在 Issue 上的 RSI-ACCEPT v1。要紧的事同时用伙伴消息把 PR 链接发给审查人。

   例外只认 QQ 在当前 head 上写的「SOP 例外已核验：<项目>」；改动工作流的 PR 一律判需要 QQ 核验。推送后读回审查人；增量用 first-parent 列出；批准绑定 commit_id。
6. 合并：用 GitHub 合并队列，作者不手动反复合 main。
7. 审查分两层，初审和终审可以同时进行；文案由 JJ 定稿；终审是 QQ，负责安全、隐私、clean-room、批准与合并。QQ 自己写的 PR 交 DD。
8. 记录和通知两样都做：决定以 PR 上的书面评论为准，绑定 head；伙伴消息不作为决定依据，但写完评论后，需要对方知道的，要用它把链接和状态发过去，只写评论对方收不到通知。
9. 每人同时最多负责 2 件实现类工作，新活由 Deja 排队。
10. 备援（按问题类型）：媒体问题交 Rea，界面问题交 DD/VV，SOP 和督查问题交 BB，都由 QQ 兜底；文案交 JJ，Deja 兜底；规则集和需要主人授权的操作，由 QQ 向主人申请。各环节超时谁接见第 4 条。
11. 新功能、产品取舍类的任务，补一句：真实痛点（没有例子就标「猜测」）→ 最小验证 → 采用或停止的条件。
12. v2 的职责、安全、隐私、clean-room、人工审批、消息送达规则全部保留。全文见 Deja 和 BB 的 SOP 文档，ADR 入库后改用正式指针。
13. 修复先实跑：主播看得到、点得到、听得到的改动，交给试剪的人、主播或初审之前，修复人自己在 Win11 的 Cindy 里用新建的临时目录，把主播完整流程走一遍，PR 里贴打码的「主播视角步骤记录」，写明实跑的 commit。只改文档、测试、CI 的写「实跑：不适用，原因：…」。例外只认 QQ 在当前 head 上写的「SOP 例外已核验：实跑」（写清原因和替代做法；head 变就失效；联网、外发、密钥不给例外）；lint 还不查这一项，由 QQ 在 review 里书面核验。全文以 v3.1 第 13 条第 3 稿（sha256 108c1382…）为准，这里没写的几项（联网时试一次点取消、状态和执行用同一个判断、没亲眼看到的承诺不写、打码范围）照全文执行。
14. 插件问题流转：做 demo 只用 MontClip 插件，不写脚本；插件的 bug 和缺的功能交 JJ，JJ 写成 Dev Spec 和 E2E 测试，交 Deja 为主的开发团队实现。
15. 问题闭环（RSI）：一个问题一张 Issue，进度只看 Issue。阶段 discovered（JJ）→ specified（PG）→ implementing（实现负责人）→ review（QQ）→ merge（Deja 定顺序，QQ 执行）→ verify（DD 写包和提交号，Video 复测）。合并不等于完成，复测通过才关闭。开单时就写负责人；暂时定不了的，写「由 Deja 在 <时间> 前排」。承接写 RSI-ACCEPT v1 评论（唯一 owner、具体下一步、reportAt）；少了「v1」巡检认不出来，会把活报成没人接。review、merge、verify 阶段的承接还要写 40 位完整 head；实现 head 变了就新增一条承接，不改旧的，绑在旧 head 上的承接巡检不认。证据写 RSI-EVIDENCE v1，绑定完整 head。评论作者是共用账号，owner 字段和第一行署名只用于归属索引，证明不了是谁做的决定，要核验实际来源；来源或内容版本核不了就不推进阶段。通知只发 Issue 链接、「完成 / 卡住 / 不接」和下一步是谁；「收到」不算回复，同一 Issue 最多追问两轮。引用巡检的「卡住多久、没人接」之前先读那张单，巡检没读到记录不等于没人做。
16. 产品决定权和授权边界：PG 在主人已确认的目标、范围、资源和现行授权内，决定产品优先级、交互取舍和最小验证的采用/修订/停止，维护北极星方向；不改写主人的目标，不免除既定验收门槛。巡检提醒到了就写正式决定，不用等主人再说一次。书面决定用 RSI-EVIDENCE v1，kind: decision，绑定当前 specUrl 及对应需求内容版本。PG 和 Deja 意见不一致，各自在 Issue 给证据，由主人定。adopt 只是产品采用决定，不替代部署或安全授权；stop 交 Deja 记录，不自动停运行任务、关闭 Issue 或回滚部署。其他分工：JJ 管需求、验收、文案定稿和素材授权台账（只记录，授权最终确认归主人）；VV 管界面体验；Video 管真实问题和 europa 复测；GG 管开源增长、品牌视觉和 Demo（对外发布前先给 QQ 看；图和视频出图时就在 PR 里写来源：工具、提示词、条款、有没有真人）；Deja、BB、Cindy 负责写代码，Deja 和 BB 做实现，Cindy 主要做查错和排障并跟进交付状态；Deja 另管工程可行性、排期、名额和合并顺序。下面这些授权只有主人能新增或变更，PG 和 QQ 都不能代给：安全、隐私、clean-room、密钥、付费、新联网或外发、对外发布、不可逆操作、权限、部署、正式批准和合并、改 SOP / 身份 / 铁律、素材授权、删除数据、新增或更换依赖 / 第三方组件 / 模型、CI 工作流和动作文件（.github/workflows、.github/actions）。已有明确授权按原范围执行，不重复索要；QQ 按现行授权负责安全门禁、正式批准和合并。
