# ADR：自动出切片卡片上的〔按歌词校准字幕〕（2026-11-03）

状态：已实现，待 QQ 审查、VV 看实窗、JJ 定两句文案。
基线：`origin/main` 0f12b26（#89 已合）。
来源：Deja 2026-11-03 批准的 8 条方案，加她补的 2 条。

## 做法

1. 时间线上的入口（字幕区〔按歌词校准字幕〕，#85 的 `openLyricsAlign`）只处理已经在时间线上的字幕。卡片在〔放到时间线上〕之前没有字幕，所以校准做在卡片上，放之前就做。
2. 弹窗部分抽成共用的 `lyricsDialog({words, caps, stale, onApply})`。时间线入口的行为不变：同样的检查、同样的 CAS、同样一个撤销步骤，原有测试和 `LYRICS_PASS` 照旧通过。
3. 卡片用这场录像的逐字稿里、中点落在卡片区间内的词（录像秒），区间就是卡片本身（`auto-slices.js` 的 `lyricScope`）。对齐和计划都用 `lyrics-align.js` 原样的 `align` / `plan`。
4. 应用时：先 `autoSnap()`，再把结果存在卡片上，即 `c.lyricCues`（录像秒）和 `c.lyricN`（改成歌词的句数）。时间线一个字都不变。弹窗里的〔撤销〕或 Ctrl+Z 一步撤回。卡片的头尾在弹窗打开后被改过，就不应用，提示「已经变了」。
5. 放到时间线上时，`autoPlaceCaptions` 对这张卡用 `lyricCues`（`lyricCuesOn`）：跟着这张卡的片段移到时间线时间，并截在这个片段之内。卡片放之前被改短的话，片段外的句子和词就不要了。别的卡照旧从逐字稿出字幕。
6. 按钮只出现在歌卡上，而且卡片区间里要有逐字稿的词（`autoLyricsAvailable(c)`）。校准之后按钮改成〔再对一遍歌词（已改 N 句）〕。
7. 全部在本机做，和 #85 一样，什么都不发出去。
8. 测试：`test/card-lyrics.test.js`（范围、对齐、放到时间线上的换算、按钮），`desktop/card-lyrics-smoke.cjs`（`CARD_LYRICS_PASS`）。

## Deja 补的两条

- **卡片上的 `lyricCues` 只存在当前窗口里**，和卡片本身一样。关掉 MontClip 再打开，卡片和校准结果都没了；已经放到时间线上的字幕会随项目保存。想把「自动出切片」的结果和项目一起存，是状态表里标「未排」的那一项。
- 〔再对一遍歌词（已改 N 句）〕的 key 是 `own.as-lyrics-again`，JJ 定稿沿用原句不改。卡片上校准完的提示 `own.as-lyrics-done` 用 JJ 的定稿：「已按歌词改好 {n} 句。放到时间线上以后，用的就是改好的字幕。」（这时时间线上还没有东西，所以不能沿用 #85 的「已按歌词改好 N 行字幕」）。这条提示带〔撤销〕，按 #92 的规则：停 8 秒，指针在上面或焦点在里面时不消失。

## 没做的

- 卡片上的校准结果不会改逐字稿，也不会影响别的卡。
- 一张卡放两次时，两次都用同一份 `lyricCues`。
- 变速片段：卡片放上时间线时速度总是 1，所以没有处理变速。

## VV 实窗复看 d545221 后补的（2026-11-03）

- 应用之后、撤销之后，焦点都放在这张卡自己的歌词按钮上，焦点始终在弹窗里。这样 Ctrl+Z 由弹窗处理，不会落到后面时间线的快捷键上。卡片会滚进可视区并短暂高亮，复用 #89 的 `autoFocusCard`。
- 校准之后，按钮的提示改成占位 key `own.as-lyrics-again-title`，文案请 JJ 定，不再显示「是听写出来的，可能有错字」。
- 这次粘贴的歌词存在卡片上（`c.lyricText`），点〔再对一遍歌词〕时会自动带进去。和 `lyricCues` 一样只存在当前窗口里：不写进项目文件，不进任何记录，也不发给 AI。测试锁住了这一点。
