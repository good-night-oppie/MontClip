# ADR：FFmpeg 探测、手动选择和首次下载（桌面版、网页版和服务器模式、Cindy 插件）

- 日期：2026-11-05
- 拍板：Deja（首席工程师）
- 产品复核：JJ（europa），2026-11-05
- 来源：主人的分工「DD 在 europa 上装好插件，边用边发现问题；JJ 复核；Deja 和 Cindy 修；QQ 和 Rea 审查并合并」。DD 用预览包实测时发现：Linux 上提示「在下面选择 FFmpeg」，但页面上没有这个入口。
- 与逆向侧隔离：本决定不引用 SPEC.md，也不引用任何逆向材料，全部来自我们自己的实测和产品判断。

## 看到的事实
- Linux：MontClip 自带的 LGPL 版 FFmpeg 没有软件 H.264 编码器，只有 nvenc、qsv、vaapi 这类硬件编码器，在 europa 上都用不了。系统的 `/usr/bin/ffmpeg` 带 libx264，用它能导出。
- 插件 PR #115（首次使用时下载 ffmpeg）在 Linux 上下载的也是 LGPL 版，所以解决不了 Linux 上导不出 MP4 的问题。另外它的 manifest 里 linux-x64 缺 `bytes`，导致 Linux 上直接报「不支持」。
- 插件里没有任何可以选择本机 FFmpeg 的界面。
- 主人 11-04 撤掉了「默认零网络」：MontClip 可以联网，但往外连之前，每次都要把目标网站和要发送的内容摆给主播看。

## 决定
1. **原则：卡片上只给「做完就真能导出」的办法。** 下载一个导不出 MP4 的版本，等于让主播白等一次进度条，她还会以为是自己操作错了。
2. **三种运行方式（桌面版、网页版和服务器模式、插件）用同一套探测逻辑。** 顺序是：内置 → 系统 PATH → 用户上次选过的路径。有好几个可用时，优先选带 H.264 编码器的那个；比如自带的 LGPL 版和系统装的完整版都在，就用系统的。找到能导出的，就什么提示都不出。
3. **没找到能导出的：** 只把预览 / 导出置灰，并写明原因；浏览、标片段照常能用，插件不崩。
   - 卡片上提到的每一个入口，都要在同一张卡片里出现：文字和控件一起生成。
   - 「重新检测」点了就生效，不用重启。
   - 手动选的路径要保存，重启后还在。
   - 不要求用户去改配置文件。预览包里那个手写 `external-ffmpeg.json` 的临时办法，不能出现在任何面向用户的文字里。
4. **#115 首次下载：保留，但按平台决定显不显示下载按钮。**
   - Windows：先实测 LGPL 版能不能用系统的 h264_mf（硬件编码器 nvenc / qsv / amf 一起测）导出 H.264。
     - 能：下载作为首选，放在卡片的第一个按钮。
     - 不能：和 Linux 一样处理。
   - Linux：卡片上不出现下载按钮，首选 `sudo apt install ffmpeg`。
   - 下载前必须有确认框，写明目标网站、大小，以及「只下载，不上传任何东西」。主播选「不用了，我自己装」，就回到手动安装 / 手动选择那张卡片。
   - 下载完马上自检能不能导出 MP4。不能的话，直接显示「还不能导出 MP4」那张卡片，不要显示「下载完成」。
5. **「找到了，但没有 H.264」要和「没找到」分开说**，用 JJ 定稿的「还不能导出 MP4」卡片。「预览照常能用」这句，要等实测确认 LGPL 版能预览以后再加。
6. **许可证：** libx264 是 GPL，只能用用户自己装的，MontClip 不能打包它。MontClip 自带和下载的，一律是 LGPL 版。

## 验收（摘要）
- 在没装 ffmpeg 的 Linux 上：卡片里每一句「点 X」，对应的 X 都看得到，附截图。Windows 上也要查一遍。
- 「重新检测」3 秒内变成「已就绪」，不用重启。
- 手动选的路径重启后还有效；选错文件时有专门的报错。
- PATH 里已经有可用 ffmpeg 的机器上，完全不出现提示。
- LGPL 版和完整版都在时，选完整版。
- Windows 上原来选 ffmpeg.exe 的流程不变。
- 文案测试：找不熟电脑的人，不问别人，能装好并导出一次（JJ 组织）。

## 还不知道的
- Windows 上 LGPL 版加 h264_mf 能不能导出。
- Cindy 插件在 Linux 上能不能弹出选择文件的窗口（弹不出来就改成填路径的输入框）。
- LGPL 版能不能预览。
- 会不会只有 ffmpeg、缺 ffprobe。
