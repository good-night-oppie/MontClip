# FLV 时间空洞：当前拒绝与后续分段导入

日期：2026-11-01。来源：Deja 本任务明确裁决。状态：当前拒绝规则保持；后续设计方向已选定，生产实现及交互尚未批准。

## 当前规则（不变）

生产 maxGap > 5ms 继续拒绝。可读区间同意、转码同意均不能越过保护；不得以 B 帧、空洞大小或 estimatedTail=false 为由豁免。无法定位或证据不足继续拒绝。不补帧、不拉伸、不静默丢弃空洞两侧，不由模型代替用户同意。本 ADR 不启用新的生产入口，也不新增容忍阈值。

## 下一独立差量：先证实可无损保留两侧，再接交互

候选方案先产出只读的空洞位置、长度和可保留区间预览；预览不得改项目。只有主播明确确认该次、该输入及这些区间后，才允许按原始顺序分段导入。两个现有同意仍分别约束各自目的，不能复用成分段同意。输入或方案变化使确认失效。

第一步只做独立合成短夹具及真实生产函数回归，不直接把间隙拒绝改为接受。用可区分的帧与音频标记验证：

- 比较空洞前后边界帧及保留段内视频帧身份，不能为了整段可解码静默移动边界或丢帧；边界不可精确实现则拒绝该方案。
- 验证两侧音频保留、原音视频相对 PTS 和各段实际产物容器 PTS，不能把视频首帧强当0或猜偏移。
- 每段独立记录输入身份/hash、流、原始保留区间及实际产物时间映射；原时基和产物时基分开，未经证明不得自动平移原字幕/弹幕。
- 先完成全部准备与校验，再经现有 project/placement/undo 一次应用；一次撤销恢复应用前项目。任一失败、取消、切项目或输入变化均不得部分注册/排布、覆盖原片或清掉已有失败状态。
- 只清理可证明本任务拥有的临时输出，保留已有文件；磁盘上的已准备文件与项目状态分别报告，不能把项目无改动写成无磁盘副作用。

建议确认卡列明源文件显示名（仅本地）、空洞时刻/长度、每段保留范围、数量及预计时间线位置，并明确不会修补空洞。以上是待 VV/JJ 审核的交互字段，不是已批准产品文案。QQ 审生产边界及失败清理，VV/JJ 审交互与措辞后再提交入口实现；模型不能自置确认。
