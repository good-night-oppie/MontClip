# ADR：把「按歌词对上片段」开给 Agent（2026-11-05）

状态：已实现，待 QQ 审查。
来源：主人要在 demo 里展示「把原版歌词丢进去，自动对上片段」；JJ 定了要开给 Agent，以及下面 7 条规则；Deja 派发。
本文是独立设计，不依赖 SPEC.md。

## 背景

剪辑器里已经有手动的歌词校准（#85 `openLyricsAlign`、卡片上的 `lyricsDialog`，都用 `lyrics-align.js`），但 MCP 工具清单里没有，Agent 驱动不了。听写在 europa 上跑不起来是另一个任务（P8）；本功能依赖听写，先用模拟的听写结果做和测。

## 规则（JJ 定，照做）

1. **只在本机算，不联网。** 对齐用 `lyrics-align.js` 原样的 `align`（逐字编辑距离），本功能不发任何东西。听写走本机现有的听写（没有听写稿的片段，先在打开的编辑器里听写一次，和 `fablecut_transcribe` 一样）。以后如果要用 AI 服务，按助手现有做法先弹确认，写清楚发出去什么、发到哪个网站；本 PR 没有用到。
2. **改之前先问主播。** 分两步：
   - `fablecut_lyrics`（risk `read`）：只出方案，不改项目。方案存在 `analysis/lyrics-proposals/<id>.json`（最新 50 份），返回 `proposalId`。
   - `fablecut_lyrics_apply {proposalId}`（risk `undoable`）：编辑器弹出现有的「AI 想做这一步」卡片，按钮是〔放到时间线上〕和〔先不用〕。她点〔放到时间线上〕才放。
   - **为什么选 `undoable` 而不是 `sensitive`：** 这一步只加一条新轨和上面的字幕，原来的东西一个字不改，⟨Ctrl⟩+⟨Z⟩ 一步撤回，正是 `undoable` 的定义。`sensitive` 的审批框写的是「这类操作撤不回，所以每次都会问你」，对这一步不是实话。规则 2 要的「每次都问」由这个工具自己保证：页面先问权限模式（计划模式只列出来、被拒的就拒），其余每种模式（手动、自动、Yolo）都弹卡片；卡片的回答也交回给模式的审批票（〔放到时间线上〕=「只批准这次」，〔先不用〕=「不同意」）。卡片不给「这个聊天中都批准」。
   - 没有打开的编辑器窗口时拒绝（没人能回答卡片），什么都不改；无头浏览器也不行。
3. **应用时新建一条字幕轨**（现有最高视频轨之上，V1…V16），原来的字幕不动，整个放置是一个撤销步骤。撤销后那条空轨还在（撤销步骤只记片段，和别的加轨操作一样），时间线上不留字幕。
4. **对不上的行不硬塞。** 每行用 `lyrics-align.js` 的 `sure` 判断（这一行的字至少一半对得上，且下面听到了字）。对不上的行不按猜的时间放进歌里：放在前后两行之间的空当里（够放才放，每行 0.5–4 秒），空当不够就排在这首歌后面，每行 2 秒；它们是灰的（`disabled`，预览和导出里都没有），`props.lyricsUnmatched: true`，留给她自己拖、自己打开。
5. **返回给 Agent 的结果：** 每行 `{text, start, end, matched, confidence}`（时间线秒；没对上的行 `start`/`end` 是 `null`；`confidence` 是这一行的分数 0–1），加上 `n`（总行数）、`k`（对上的行数）、`m = n − k`、`code` 和两种语言的 `message`。
6. **文案按 JJ 定稿**，中英文都在 `ui-preferences.js`（`own.lt-*`），`test/lyrics-track.test.js` 逐字锁住：
   - 方案预览 `lt-preview`、放好以后 `lt-done`、对上得太少 `lt-too-few`、没有人声 `lt-no-vocals`、没有歌词 `lt-no-lyrics`。
   - 需要听写、但引擎不能用：`lt-asr-unavailable`。**TODO(P8)：** 这句要沿用 P8 定稿的那句，那句还没定稿，现在只是占位，测试只锁 key 在、不锁字。
   - 卡片按钮〔放到时间线上〕〔先不用〕用 JJ 的中文；英文 "Put on the timeline" / "Not now" 和「先不用」之后的提示 `lt-not-placed`（「没有放，什么都没改。」）是新写的，待 JJ 看。
7. **边界：不认歌。** 歌词是她自己贴的。界面、工具说明和返回结果里都没有「识别出是哪首歌」之类的话，也不调用 `song_lookup`。测试检查文案和工具结果里没有这类字眼。

## 门槛：对上 ≥ 20% 的行（且至少 2 行），才放到时间线上

数据：`scripts/lyrics-threshold.cjs`，模拟「TTS 念歌词＋伴奏，本机引擎听到的字」（`test/lyrics-synth.js`：四首为测试写的原创歌词，每首 10 行；每个字 0.28 秒，行间换气 1.2 秒；伴奏的影响模拟成一部分字听错成别的常用字，再加上漏字、多字，各 1/4 错误率；每种情况 20 个随机种子）。结果（k/n）：

| 情况 | 最低 | 平均 | 放上去的 |
|---|---|---|---|
| 歌词对，0% 听错 | 1.00 | 1.00 | 80/80 |
| 歌词对，10% 听错 | 0.80 | 1.00 | 80/80 |
| 歌词对，20% 听错 | 0.80 | 0.97 | 80/80 |
| 歌词对，30% 听错 | 0.40 | 0.85 | 80/80 |
| 歌词对，40% 听错 | 0.30 | 0.70 | 80/80 |
| 混进 3 行不存在的（共 13 行），20% | 0.62 | 0.74 | 80/80 |
| 同上，30% | 0.31 | 0.65 | 80/80 |
| 同上，40% | 0.23 | 0.54 | 76/80 |
| 换了一首歌，0% / 20% / 40% | 0.00 | 0.00 | 0/60 |

换歌的一侧每次都是 0：一行要有一半的字对得上才算对上，偶然重合的常用字不够。对的一侧最差到 0.23。门槛定 0.2：模拟里所有对的情况都能放（混进假行又听错 40% 的那 4 次例外，它们已经低于 0.2），和换歌之间留出了很宽的距离。另加「至少 2 行」，防止一行碰巧对上就把整首放上去（只有 1 行的歌词，那 1 行对上就行）。

**限制：** 这是模拟的听写结果，不是真的 TTS 声音过真的引擎——CI 里两样都没有，本机（Windows）也没有中文 TTS 和听写模型。P8 修好以后，应该用真录音（或真 TTS＋伴奏）再跑一遍这张表，必要时调门槛；`scripts/lyrics-threshold.cjs` 跑完会在门槛分不开两侧时退出码为 1。

## 实现

- `lyrics-track.js`（纯函数）：`propose`（调用 `lyrics-align.js` 的 `lines` / `align`，不另写对齐）、`place`（每行放在哪）、`clips`（新轨上的字幕片段，用 `captions.js` 的 `clip`，对上的行按字计时）、`newTrack`、`scopeSig`（唱歌那几段的位置、源区间、速度和帧率；方案之后动过就拒绝）、`forAgent`、`messageKey`。
- `mcp-server.js`：`fablecut_lyrics`、`fablecut_lyrics_apply`。听写复用 `speechWords`；听写本身跑不起来时返回 `ASR_UNAVAILABLE`。
- `server.js` `POST /api/lyrics/request` → 导出任务队列里的 `lyrics` 任务（`export-jobs.js`：只给打开的窗口，没有就 409 `EDITOR_NOT_READY`）。
- `app.js` `runLyricsJob` / `lyricsCard`：问权限模式 → 卡片（每 10 秒报一次心跳，Agent 取消时卡片关掉）→ 再查一次 `scopeSig`（CAS）→ 加轨、放字幕、一个撤销步骤 → 存盘 → 回报 `{applied, track, placed, grey, revision}`。
- 插件：`MontClip-Cindy` 要转发这两个工具时需要改的，写在 PR 里；本 PR 不改那个仓库。

## 版权边界（待主人定）

demo 里用的歌词是有版权的文字。建议：

- 画面上只露几行，或者只用她直播间里本来就显示的那几行，不要把整首歌词贴满屏幕。
- 工具说明里要求 Agent 回给用户时只引几行，不复述整首。
- 歌词只在本机处理，不发出去；方案文件留在 `analysis/` 里，和听写稿一样。
- 测试和脚本里只用为测试写的原创歌词。

最后怎么判断（能露几行、哪些场合能用、方案文件要不要用完就删），要主人来定。

## 没做的

- 应用内助手的计划步骤（`agent-plan.js`）还执行不了 `fablecut_lyrics_apply`，会停在「助手现在还做不了这一步」。这一步现在只走 MCP。
- 撤销后留下的空轨不会自动删。
- 没有真录音、真 TTS 的测试（见上面的限制）。
