Transcripts and text-based editing

Turn speech into words with times, in the browser, then read, search and cut the edit like text: in the Transcript tab, or from an agent with fablecut_transcribe.

MontClip turns the speech in a clip into words with times, so an edit can be read, searched and cut like text. Transcription runs on this computer, in the editor's local server (asr-local.js; MontClip #70, Deja 2026-11-03): ffmpeg reads the file's sound, the silero VAD finds the speech, and sherpa-onnx-node 2.0.1 runs the Paraformer zh model (sherpa-onnx-paraformer-zh-2023-09-14, int8, 232 MB) on each stretch of it, with per-character times; the CT-Transformer model adds punctuation when it is installed (optional, 76 MB). Nothing is sent anywhere.

The model hears Mandarin, with English words mixed in. Chinese words are single characters and read without spaces (MontClipTranscribe.join); English words keep their spaces. On the europa benchmark (~/asr-bench/RESULT.md, measured there, not here): FLEURS character error rate 3.33% on Chinese characters, 4-thread real-time factor about 0.05. On the Win11 test machine (i7-11800H) a 10-minute recording took about 15 s (decoding RTF 0.028). Singing is transcribed with many wrong characters.

Where the model comes from (desktop/asr-manifest.json pins every file's SHA-256 and size; a file that does not match is never used):

  • the 完整版 package carries both models (resources/asr/models);
  • otherwise the Transcript tab offers Download - the desktop main process asks first (size and sites), then fetches from hf-mirror.com (pinned commit), else the k2-fsa GitHub release, following redirects only to the hosts written in desktop/main.js (ASR_HOSTS). Downloads resume with HTTP Range from asr-models/.partial/<sha256>.part; a finished file is checked before it is renamed into place, and one that fails is deleted (ASR_CHECK_FAILED); a dropped connection or Cancel download keeps the part (ASR_DOWNLOAD_INTERRUPTED); too little disk space is said first (ASR_NO_SPACE) - or Import from a USB drive or a file: pick a folder; model files (and the official .tar.bz2 archives) are recognised by their SHA-256, whatever their names. Downloaded and imported models live in the app's user data (asr-models/).

The first time the desktop app opens without a model, a setup page asks: transcribe on this computer (download), or not now; it shows the download's states (downloading, done, network gone, no room, a file that failed its check). Settings › Transcription reopens it. The choice is kept by the main process (asr-choice.json).

The engine and the VAD are in every package. GET /api/asr/status says what is there; without the model, transcribing answers ASR_MODEL_MISSING and downloads nothing.

One transcript per file, kept by the server in analysis/transcripts/: {v, src, model, language, duration, created, words:[[text, start, end], …]}, times in seconds of the file. Like a proxy it belongs to the file's size and modification time, so a replaced or re-rendered file has none until it is transcribed again. It is not stored in project.json, so it never bloats the timeline, and every clip and sequence that uses the file reads the same one.

On the timeline a clip shows the words its window of the file holds, placed through its in point and speed (a word counts when its middle is inside the clip). A clip with a speed ramp is left out, and so are disabled clips and pictures whose sound is off.

Cutting words extracts on the targeted tracks, from just before the first word to just before the word after the last one: the pause after the cut goes too, the pause before it stays. Cuts land on whole frames, never in a neighbouring word or past the clip. Several cuts go last first, as one undo step (one revision for an agent): later material moves up, linked stems stay in step, and locked clips stay put - lock the music bed first if it should keep running under the tightened edit. Find matches whole words and ignores case, accents, punctuation and spacing: "ai powered" finds "A.I.-powered", and "cat" doesn't find "category".

In the editor, the Transcript tab beside the Inspector:

  • The model line says whether the speech model is ready, with Download and Import from a USB drive or a file when it is not (and Download the punctuation model when only that is missing).
  • Transcribe works on the selected clips' files, else on every file on the timeline that has no transcript yet. Progress shows below, with Cancel.
  • The timeline's words, in paragraphs with timecodes. Click a word to go there; the word under the playhead is underlined and followed while playing. ⇧-click or drag to select a run of words, then press Delete (or Cut) to extract it.
  • Find words marks every match, Enter steps through them, and Cut N extracts them all. Copy copies the text with its timecodes.

Agents use fablecut_transcribe. It transcribes through an open editor tab (else headless Chrome / Edge), which asks the local server:

  • {} transcribes every clip with sound that has no transcript yet, then returns the timeline's words as timed lines: [0:12.08] 打开演示，不用安装。 clipIds limits it to some clips; from / to limit the time (the reply stops at 300 lines); mediaIds reads whole files in file seconds instead.
  • again:true transcribes again. (model is paraformer-zh, language is zh.)
  • When the speech model is not installed the reply says so: tell the user to download or import it in the Transcript tab; never fetch it yourself.
  • find:"phrase" (or a list) reports each place it is said, with its span, the words around it and how much cutting them would remove; cut:true extracts them (tracks and force as for fablecut_silence). A version of the project is kept before the cut. A Chinese phrase matches any run of characters.

The model writes clean text: it often leaves out fillers and false starts, so find those by ear (fablecut_silence for the pauses), not by text. Character times are good to about a tenth of a second; listen to a cut that matters, or check it with fablecut_frame.
