# 项目文件被改回更旧的版本时，要告诉用户，不要静默忽略

QQ 的不阻塞建议（2026-11-02，审 #43 时提出），之后单独开 PR 做。

## 现状

#43 之后，页面重新加载时如果拿到的项目文件比自己的版本更旧（revision 更低），就直接忽略，继续显示自己的版本，不会提示。

这样做是为了修一个竞争：重新加载的请求在本地保存之前发出，在保存之后才返回。返回的是保存前的旧文件，按原来的逻辑会被当成「外部修改」应用，页面就回退了。

## 要加的

如果收到的回应**严格更旧**，并且**不是自己正在保存的那份**，在界面上提示「项目文件被外部改成了更旧的版本」，不要静默忽略。

## 难点：别把 #43 那种情况当成外部回退

迟到的旧回应（#43 那种）和真正的外部回退，在收到时看起来一样，都是一份更旧的文件。一律提示的话，正常编辑时也会偶尔误报。

一个可行的区分办法：忽略一份更旧的回应之后，等本地正在进行的保存结束，再读一次磁盘上的文件。

- 磁盘已经和本地一样，或者比本地更新：说明那份只是迟到的旧回应，不提示。
- 磁盘仍然比本地旧：说明文件确实被外部改回去了。比如服务启动时把损坏的文件恢复成了最近一份好的，或者有人把旧备份拷了回去。这时提示用户，并且不再自动保存覆盖它，让用户选择保留哪一份。

## 需要先定的

- 提示的文案（交 JJ）。
- 真正回退时让用户怎么选：「用磁盘上的版本」/「保留我现在的」。选「保留」时，下一次保存需要用比磁盘更高的 revision 写回去。

## 怎么算做完

- 迟到的旧回应不提示（#43 的测试仍然通过）。
- 磁盘确实回退时一定提示，而且不会在用户选择之前自动覆盖。
- 两种情况各有测试。
